1. Why the surface looks like a waffle

Original script.js:880–884 creates a rest-position sine pattern with fixed frequencies 165 and 220 radians per display unit. Lines 932–934 add normal offsets of 0.24 and 0.26 regardless of --ts-shirt-bump. Line 915 also subtracts a fixed 0.12 roughness variation. Lowering the CSS bump to 0.01 only weakens the UV normal map; this second relief layer remains. This is not a CSS cascade override: it is an independent shader contribution that can dominate the look.

--ts-knit-repeat:289 affects UV textures, not those fixed rest-space frequencies. The texture already contains 24 by 36 cycles per tile (script.js:147–148), so this means 6,936 horizontal cycles over one UV unit. At a distance much of that detail filters away while the coarse rest-space pattern remains. The fixed cosine offsets are also a stylized normal perturbation rather than the exact gradient of the combined V-stitch height field.

style.css:92 contains --ts-ao-intensity:0,5. Custom properties accept this text, but parseFloat('0,5') returns zero at script.js:92; the fallback is not used. Use 0.5. AO only changes rendering if an AO map is present. The loader's fallback from aoMap to map is not a reliable AO conversion: a colored base map is not measured occlusion. Also, --ts-wall-roughness:3.5 is outside the conventional 0–1 material range.

The copied script exposes micro strength, wale/course frequency and roughness variation as CSS tokens. It attenuates unresolved waves using derivatives to reduce distant shimmer. The copied CSS fixes AO and wall roughness. Moving cursor/turn telemetry onto the child frame prevents those writes from triggering the root's material observer; the observer batches real changes once per animation frame and skips unchanged token sets. Changing data-fabric updates the material. Stylesheet edits still require a reload or window.syncTShirtCssTokens(); observing a root attribute cannot detect arbitrary stylesheet or ancestor edits.

3. Six-part desktop full-screen speedup plan

No FPS improvement is claimed without before/after measurements. Compare the same browser, GPU, camera, lighting and viewport at 1920×1080 and 3840×2160. Warm the scene, record 10-second idle, flip, pointer-motion and zoom runs, and report median/p95 frame time, GPU time where available, draw calls, triangles, texture memory and load time. For both render passes, set renderer.info.autoReset=false and reset once per frame so counters include the whole frame.

  1. Reduce geometry first. The GLB JSON reports 199,600 vertices and 1,119,840 triangle-list indices: exactly 373,280 triangles in one mesh. Draco compression explains the 933,304-byte download; it does not reduce decoded triangle count. Export candidate LODs around 40k, 60k and 80k triangles inside this subfolder. Preserve collar, sleeve/hem silhouette, UV seams and normals; use seam-aware simplification or retopology. Compare silhouettes and close-up printing at maximum zoom before choosing an LOD. Start with 60k as a candidate, not a guaranteed visual threshold. Re-bake normal/AO detail where needed, then compress the selected asset. Verify loader compatibility with Three r128.
  2. Run DoF at half width and half height. Keep the sharp scene color/depth full-resolution; downsample color/depth-aware CoC, blur into a half-resolution target, then depth-aware composite into full-resolution output. Blur pixel work becomes one quarter, not one half. The existing code renders its DoF quad directly to the full-resolution default framebuffer: merely shrinking the input target will soften the shirt but will not reduce the output shader invocation count. Keep sampling resolution distinct from output resolution. Convert CSS blur radius to half-resolution texels with radiusCSS*dpr*0.5. Avoid foreground/background halo leaks by comparing depth/CoC during gather and upsample. Apply tone mapping/output encoding once in the final pass. Test hairline logo edges, collar boundaries and near/far blur.
  3. Remove observer feedback. Original pointermove writes two root styles; the root observer loops every mutation and re-reads all tokens/materials. Flip telemetry does the same. The prototype isolates telemetry on the frame, batches material sync and compares token values. Next cache pointer coordinates and apply telemetry at most once per frame; refresh bounds on resize/scroll. Verify one CSS sync per actual configuration change and zero root material syncs from pointer motion alone.
  4. Use a pixel budget. Original DPR is capped at 1.35, but a 4K canvas still has roughly 15.1 million pixels at that DPR. Compute dpr=min(deviceDpr,1.35,sqrt(maxPixels/(width*height))), allowing a value below 1 for a deliberate large-display quality tier. Use renderer.setPixelRatio before setSize, then resize all targets from the actual drawing buffer size. The original resize path computes a new DPR but does not set it on the renderer. Add hysteresis and a settling interval for adaptive quality; avoid oscillating target allocations during interaction.
  5. Control shadow cost. A 1024² shadow pass still transforms the dense shirt. Reduce geometry first, then test 512/1024 shadow maps and tighten the light frustum. The sun moves every frame, so caching shadows while retaining motion gives stale lighting. For a static quality tier, freeze the sun and cloth animation, update shadows on flip/scene changes, then disable automatic shadow updates. With moving cloth, match shadow deformation through a custom depth material; the original injected vertex breeze is not automatically reproduced by the depth pass.
  6. Schedule and simplify work. Combine document visibility and viewport intersection with AND, using separate flags; the original shared flag can be overwritten by either event. Suspend offscreen rendering, support reduced motion, and use demand rendering only after disabling idle sway, breeze and moving lights. Skip the blur gather when blur is zero while retaining the final color transform. Dispose replaced geometry/materials/textures and old logo textures with ownership tracking; shared textures must not be disposed while in use. Measure shader texture taps before removing detail that users can see.

4. Exact 30 × 40 cm print bounding box

Keep physical design coordinates separate from preview scale. Store the printable rectangle in centimetres: width 30, height 40. Choose a measured collar-to-hem or other landmark distance Hcm, measure the same landmarks after import normalization as Hmodel, and define s=Hmodel/Hcm. Do not infer centimetres from screen pixels or assume the current display normalization means metres. The loader conditionally rescales the largest span to 3.10 units and recentres the mesh; store that transform or calibrate afterward. The GLB bounds alone do not establish a real-world shirt size.

W = 30*s; H = 40*s
xMin = cx - W/2; xMax = cx + W/2
yMin = cy - H/2; yMax = cy + H/2
front UV = ((restX-cx)/W + 0.5, (restY-cy)/H + 0.5)
back  UV = ((-restX-cxBack)/W + 0.5, (restY-cyBack)/H + 0.5)

Size L calibration supplied by the user: 55 cm across the bottom hem. Measure Bmodel between the left and right bottom-hem landmarks in the normalized rest pose, excluding sleeves. Use s=Bmodel/55. Then W=(30/55)*Bmodel=0.5454545455*Bmodel and H=(40/55)*Bmodel=0.7272727273*Bmodel. A centred print leaves 12.5 cm on each side relative to that hem span; this is not a guarantee of chest clearance on a tapered shirt. The hem is measured flat across, not as circumference or projected screen width. This calibration assumes uniform scale and a garment model whose proportions represent the chosen size L; a nonuniformly stretched model requires separate horizontal and vertical calibration.

The existing scale option sets print width and derives height from image aspect. Set the print texture to 3:4 aspect or introduce independent rectangle width/height uniforms. The original front offset of 0.42 does not define a centred physical print area. Vertical placement remains an independent collar/print-centre landmark, to be checked against the actual torso.

Allocate a transparent design canvas at a 3:4 aspect ratio, place art within it using fit=min(30/artWidth,40/artHeight), and pass separate width/height uniforms for the print rectangle. Preserve aspect ratio and transparent margins. Clip outside the rectangle in the fragment shader; retain front/back normal and torso masks to prevent sleeve or reverse-side leakage. Check the entire rectangle against the actual garment's printable panel; reject or flag a box crossing a collar/hem/seam rather than silently resizing the promised 30×40 area. Project the same rest-space coordinates through the same animated deformation for the guide, so it stays aligned during sway and flip.

A 30×40 cm print at 300 dpi is approximately 3543×4724 pixels after rounding; store 30×40 cm as authoritative metadata because integer raster dimensions introduce rounding. Preview/export separation matters: garment lighting and folds belong in a mockup, not the flat print artwork. Planar projection specifies a flat design rectangle, not exact geodesic distances on a folded 3D surface. Manufacturing-grade placement needs a calibrated garment pattern/UV panel or physical template. Never advertise the uncalibrated preview as a verified print template.

5. Scroll and pinch zoom architecture

Use a single controller state {zoom:1,targetZoom:1,min:1,max:2.5,pointers,gestureMoved}. Bounds are initial UX choices to validate against geometry and camera near plane. Store zoom independently of the responsive camera fitter. Each frame compute the base camera position from the existing orbit, then apply position=target+(basePosition-target)/zoom. Smooth zoom with alpha=1-exp(-12*dt). Update focus from the final camera position, not the pre-zoom base distance. A direct wheel handler that changes camera.z will be overwritten by the current animation loop.

Wheel: normalize deltaMode to pixels (line -> configured line height;
       page -> stage height), then targetZoom *= exp(-deltaPixels*0.0015).
Pinch: on second pointer, store startDistance and startZoom;
       targetZoom = startZoom * currentDistance/startDistance.
Both: clamp targetZoom; use finite positive distances; smooth in animation loop.

For wheel capture use a non-passive listener only on the stage. Prevent default only while the component is actively consuming zoom; release at bounds so the document can scroll. Preserve browser accessibility zoom for Ctrl+wheel by default. For explicit pinch manipulation use touch-action:none only on an opt-in interactive stage, with visible +/−/reset controls and keyboard equivalents; otherwise preserve page touch gestures.

Track each pointerId, use setPointerCapture, and clean up on pointerup, pointercancel and lostpointercapture. A multi-touch session sets a sticky “gesture occurred” flag until every finger lifts. Suppress flip after any pinch or drag, including when the second finger lifts first. Retain the current under-8-pixel/under-500ms tap rule only for a single pointer with no gesture history. On resize preserve zoom and recompute the fitted base camera. On flip preserve zoom but check silhouette/camera collision at side-on angles. Pause idle camera sway in inspection mode so detailed artwork can be examined steadily.

Acceptance cases: 30×40 box under two calibrated garment sizes; portrait/square/landscape art without distortion; front/back lettering orientation; clipping at print boundaries; wheel and trackpad; pinch in either release order; cancelled touches; no accidental flip; keyboard zoom/reset; resize while zoomed; no camera clipping; updated DoF focus; unchanged physical print dimensions after zoom.
